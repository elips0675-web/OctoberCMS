## 4. Отклонено

- **Fortify, CSP-плагин, Meilisearch, RainLab.Revisionable, Spatie Backup как
  плагины.** Правило «один плагин `nlb/library`» (`AGENTS.md`, правило 5,
  `docs/plugins.md`) не отменяется: то же делается кодом плагина или
  штатными таблицами. Исключение — только из списка `docs/plugins.md`.
- **Замена `Content::flush()` на тегированный кэш сейчас.** Кэш запроса не
  переживает запрос; теги появятся вместе с полностраничным кэшем, иначе это
  кэш ради кэша.
- **«Универсальные пути» вместо `D:\nlbbootstrap-main` в документации.**
  Источник миграции — часть условия задачи (`AGENTS.md`, §1), его путь должен
  быть точным. Машинные пути PHP/Composer остаются в `README.md` и
  `docs/installation.md` как инструкция для этой машины.
- **Snapshot-файл `.ai/context-snapshot.md` и `docs/ai-examples/`.** Их роль
  уже выполняют `Что сделано.txt` (что и чем проверено) и код проекта;
  третий журнал протухнет молча.

## 7. Как этим пользоваться

1. Перед новой работой — сверить пункт с этим документом: если он здесь
   «отклонено», второй раз не обсуждать.
2. Закрытый пункт бэклога удаляется из `Что доделать.txt` и попадает записью
   в `Что сделано.txt`; строку в таблице §2–3 тогда править не нужно —
   она ссылается на номер пункта, а номер исчезает вместе с пунктом.
3. Оценка не является источником факта: числа (тесты, адреса, размеры)
   берутся из прогона, а не из HTML.

## 8. WPShop: что применимо к этому сайту

## 9. Конструктор страниц Qwen: разбор черновика перед реализацией

Третий черновик владельца (`конструктор страниц Qwen.html`, 12.11.2026, 12,4 КБ)
описывает тот же конструктор, что и §8, но с готовым YAML. Подход совпал с
принятым — Tailor `repeater` + `displayMode: builder` + партиал на группу, —
поэтому черновик лёг в основу P2-24 (Stage 20). Отличия проверены по коду:

| Тезис черновика | Что показала проверка |
|---|---|
| `blueprints/page.yaml`, `handle: Page` без `type` | **Не загрузится как есть.** Ядро отбрасывает blueprint без `type` (`modules/tailor/classes/Blueprint.php:458-467`), верификатор требует одно из поддерживаемых значений (`modules/tailor/classes/BlueprintVerifier.php:164-165`). Плоский файл в `blueprints/` ядро поддерживает (`modules/tailor/tests/classes/BlueprintDbLayerTest.php:239`), но конвенция плагина — каталог на blueprint: `blueprints/page/structure.yaml` |
| `{% partial 'blocks/' ~ block._group %}` | **Ошибка имени поля.** В ядре группа называется `content_group` (`modules/tailor/models/RepeaterItem.php:48`, `:222`); `block._group` дал бы путь `blocks/` и ошибку Twig. В шаблоне — `block.group` из `PageBuilder::prepare()` |
| `dropdown: optionsFrom: categories` | **Ключ не поддерживается в полях.** `optionsFrom` живёт только в фильтрах списков (`modules/backend/classes/FilterScope.php:24-51`), список разделов остался бы пустым. Разделы перечислены явно (`options:`), совпадение с белым списком кода проверяет тест |
| `book_grid` с `category_id` | **Заменено на универсальную сетку:** источник — белый список разделов, лимит 1…12 (`PageBuilder::SOURCES`, `MAX_LIMIT`), выборка — `Content::records()`. Раздел `books` — «Сувениры и подарки» (см. §8), числовых `category_id` в данных нет |
| `prompt:` у повторителя | **Поддерживается** — заголовок палитры блоков (`modules/backend/formwidgets/repeater/partials/_repeater_toolbar.php:8`) |
| `displayMode: builder` + `groups` | **Поддерживается** — эталон ядра `modules/tailor/tests/fixtures/blueprints/landing/blockbuilder.yaml:9-13` |
| «`check-dom-parity` контролирует разрастание DOM» | **Неверно для новых страниц.** Гейт сравнивает ровно 110 HTML эталона (`tools/check-dom-parity.mjs:108-111`); собранных страниц в нём нет и быть не может. Защиту держат `PageBuilderTest` (группы ↔ партиалы, разделы ↔ белый список, классы ↔ CSS) и бюджет CSS |
| Адрес, 404, SEO, карта сайта | **В черновике отсутствуют вовсе** — это и есть недостающая часть: без wildcard-страницы запись из админки не открывается по адресу. Сделано: `themes/nlb/pages/builder.htm` (`url = "/:slug"`), `PageBuilder::find()` + `applyVisibleFrontend()`, 404-ветка, `Seo::applyRecord()`, `Sitemap::urls()` |
| «Не плодите микро-SEO поля» | **Принято с оговоркой:** у собранной страницы нет своего текста, из которого можно вывести описание, поэтому `excerpt`/`seo_title`/`seo_description` — источник, а не дубль |
| «CSS ≤ 56,4 КБ», «0,5 секунды» | Первое — наш бюджет (`tools/check-css-budget.mjs:32`), второе — непроверяемое обещание. Проверяемое требование этапа: один запрос к БД на блок, блоки без JavaScript |
| Плагины `PageTree`/`Boxes`, лайтбокс, шорткоды, конструктор шапки | **Отклонено раньше** — §4 и §8 |

Итог по 12 тезисам: подход совпал, три технические ошибки в YAML (нет `type`,
`_group` вместо `content_group`, несуществующий `optionsFrom`) и один
отсутствующий слой (маршрут, 404, SEO, карта сайта) — он и стал основной
работой Stage 20. Принято в реализацию: `displayMode: builder`, `prompt`,
группы блоков, документ для контент-менеджера.

## 10. Монетизация: что верно, что нет и что это стоит

Четвёртый черновик владельца («Как монетизировать шаблон и функционал для
October CMS deepseek.html», 13.11.2026) — не про код сайта, а про упаковку
продукта. Проверено по репозиторию; подробный план — `docs/monetization.md`.

| Тезис черновика | Что показала проверка |
|---|---|
| «Ядро October v4 под MIT» | **Ошибка, и дорогая.** В корне `LICENSE.md` — EULA: ключ на один сайт (`LICENSE.md:27`, `:109`) и запрет «sublicense, resell, distribute, or transfer the Licensed Software» (`LICENSE.md:35`, `:140`). Наш собственный документ это уже фиксировал: первая лицензия бесплатна, обновления `$39/год` (`docs/plugins.md:11-15`) |
| «Regular / Extended License» | Термины Envato; в October Marketplace своей модели лицензий, этих двух нет. В документации продукта смешивать нельзя |
| «Комиссия маркетплейса 30 %, PayPal» | Внешний факт, в репозитории не проверяется — так и помечено |
| «`screenshot.png` обязателен» | Требование карточки Marketplace, ядром не используется (в `modules/cms`/`modules/backend` строки `screenshot` нет). У нас файла нет |
| «`version.yaml` обязателен для темы» | **Необязателен:** без файла история версий пустая (`modules/cms/classes/ThemeManager.php:391-393`) |
| «Убрать локальные пути» | Верно и дёшево: такой путь ровно один — `plugins/nlb/library/console/Import.php:65` (`D:/nlbbootstrap-main/…`) |
| «Сменить вендора `nlb/library`» | Дороже, чем звучит: `Nlb\Library` в **75** файлах (60 с `namespace`), плюс карты разделов в `Content`, `Sitemap::SECTIONS`, `Seo::SECTIONS`, JSON-LD и тестах. Таблицы `xc_*` от UUID переживут, но карты надо править синхронно |
| «Вынести хардкод в `theme.yaml`» | Объём: «Библиотека 2026» — **61** вхождение, телефон/адрес — **26** строк, часть в `assets/js/script.js` (файл побайтово равен источнику) |
| «Тема упаковывается через `composer.json`» | Верно и обязательно: без `composer.json` в теме `ThemeManager::getComposerCode()` вернёт пусто (`modules/cms/classes/ThemeManager.php:354-366`), второго кода — `authorCode` в `theme.yaml` (`:229-231`) — тоже нет |
| «`theme:seed` для демо» | **Верно:** команда есть (`modules/cms/console/ThemeSeed.php:34`), читает `seeds/blueprints` и `seeds/data.yaml` и сама мигрирует Tailor (`modules/cms/models/ThemeSeed.php:150`, `:165`) |
| «`migrate:fresh --seed` достаточно» | **Нет:** Tailor-таблицы создаёт `tailor:migrate`/сид темы; без шага новая страница отдавала 500 (проверено в Stage 20) |
| «Демо-админка `demo`/`demo`» | Небезопасно на публичном стенде: бэкенд за `adminAuth`, но пара подбирается. Нужен демо-аккаунт только на чтение и сброс вместе с БД |
| «Lighthouse 100/100/100/100 из коробки» | Не подтверждено: домена нет (M17), `tools/cwv-report.mjs` отсутствует, замеров нет — это цель, а не факт |
| «Админка как AdminLTE» | `baba-adminlte` — **фронтенд**-тема 2020 года (1.0.0, «v4.x not tested»), к бэкенду отношения не имеет. В 4.4 админка настраивается штатно: `brand` в `config/backend.php:45-62` (6 палитр, light/dark/auto, 5 режимов меню, свой CSS), глубже — скин `Backend\Classes\Skin` |

Итог: продавать можно, но «MIT» — ошибка, требующая правки в любом тексте
продукта; упаковка стоит не «два дня», а четырёх пунктов бэклога P2-26…P2-29
(упаковка, демо, тумблеры элементов, брендинг админки). Всё проверяемое
зафиксировано в `docs/monetization.md`.

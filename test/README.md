# Папка `test` — вход для внешнего AI-аудита

Репозитории: продукт — `D:\October CMS` → https://github.com/elips0675-web/OctoberCMS,
витрина — `D:\Elv Landing` → https://github.com/elips0675-web/elvstudio,
стенд — `D:\Elv test` → https://github.com/elips0675-web/Elvtest.

Здесь лежит **самодостаточный срез продукта** для анализа в браузере
(DeepSeek, Qwen и другие модели без доступа к диску).

| Файл | Что внутри |
|---|---|
| `Для анализа.txt` | стек, роли площадок, что откуда (ядро/магазин/кастом), карта кода, тесты и гейты, факты HEAD, бэклог, ограничения, вопросы аудитору |

## Как пользоваться

1. Открыть `Для анализа.txt` и загрузить его в чат целиком.
2. Задать вопросы из раздела «Что смотреть аудитору» или свои.
3. Если модели нужен конкретный файл — назвать путь из карты кода
   (`plugins/elv/library/classes/Seo.php` и т. п.); этот файл ей отдельно
   и передать.

## Что здесь **не** лежит

- Код, `.env`, пароли, дампы БД.
- Документы `AGENTS.md`, `README.md`, `docs/*` — они остаются в корне
  и в `docs/`; в срезе даны ссылки и выжимка.
- Полный бэклог и журнал — `Что доделать.txt` и `Что сделано.txt` в корне.

## Когда обновлять

- После каждого закрытого этапа: меняются числа тестов/гейтов, статус
  упаковки, бэклог — править разделы 6–8 и дату среза в шапке.
- Перед отправкой на аудит проверять, что HEAD совпадает с указанным
  коммитом (`git log --oneline -1`), а числа — с фактическим прогоном.

Файл коммитится в репозиторий (`test/` не в `.gitignore`).
